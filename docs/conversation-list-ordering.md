# 移动端会话列表排序

更新日期：2026-10-16

## 排序契约

列表接口在分页前完成排序。首次加载、进入侧边栏、下拉刷新和翻页均请求列表，客户端保留接口返回顺序，不对单页重新排序。

本地收到交互更新或置顶状态变化时使用同一规则：

1. 置顶会话优先，普通会话随后。
2. 组内按 `lastMessageAt` 倒序；为空时使用 `createdAt`。
3. 时间相同按 `id` 倒序。

`updatedAt` 和置顶时间不参与时间排序。兼容旧响应同时缺少两个时间字段时，使用固定时间兜底并按 ID 稳定排序，不使用客户端当前时间。

## 交互时间与 SSE

`lastMessageAt` 由后端维护，表示发送消息、推荐或采用选题、确认生成等最近一次用户主动交互。客户端复用现有 SSE，从任何事件的 `payload.lastMessageAt` 读取时间，仅接受比本地更晚的有效值。

收到更新时合并对应会话并调整本地顺序，不为该事件重新请求列表。Agent 回复、流式文字、任务进度及重命名未携带新交互时间时保持顺序；发送失败也不改变交互时间。

## 分页与并发

- 当前仅展示第一页：本地更新并重排，保留置顶优先级与每页 20 条限制。
- 已加载后续页：新交互发生后恢复缓存的第一页，加入被更新的会话，重排并滚动到顶部；无第一页缓存时请求第一页。
- 在途翻页遇到新交互时取消，迟到的响应不追加回列表。纯元数据更新不取消翻页，也不重排或返回第一页。
- 列表响应与本地数据按会话 ID 合并：元数据取较高 `revision`，`lastMessageAt` 独立取更晚的值。
- 在途第一页响应遗漏刚移入第一页的会话时，保留本地记录并重排，避免顺序回退。
- 置顶、创建、归档改变分页偏移时，后续翻页先从第一页校准。
- 切换账号或退出登录清空该账号的合并记录和分页缓存，取消旧请求。

## 实现位置

- `ConversationSession`：解析创建时间与交互时间，合并元数据版本和时间。
- `SessionRepository`：列表保留服务端顺序，本地更新时提供统一比较规则。
- `applyConversationEvent` / `ConversationController`：传播 SSE 交互时间，无新时间的文字和进度事件不触发列表更新。
- `SessionsController`：合并在途响应、分页缓存及本地顺序调整。
- `PopiDrawerSessions`：进入时刷新列表、翻页及恢复第一页后的滚动复位。
