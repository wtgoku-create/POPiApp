# DSH 风格短片交互与接入设计

更新日期：2026-10-25

将 Lemo Opuscar 作为 DSH 的一项创作能力，在原会话中完成选风格、定方案、审分镜、制作和修改。Bot 能力开关名称为“制作风格短片”，创作流程简称“风格短片”。Web 提供可并排查看方案与画面的工作区，移动端提供逐步细化的全屏页面；两端共享同一个任务、草稿和作品版本。

App、DSH 配置、结构化请求、持久分镜审核、受控渲染及私有资产链路已经实现。目录固定同步上游版本的 59 种风格；首版提供 `impasto`、`ink-wash`、`swiss-motion`、`paper-lantern`、`pixel-rpg`、`blueprint` 六个受控 2D 适配器，其余 53 种保留在目录中并显示不可制作原因。客户端只允许选择服务端 `ready=true` 的条目；ready 由源码资源指纹、模型与运行环境、规划工具、渲染器和私有存储的运行检查共同决定，不以客户端字段或人工艺术评分开启。

## 能力边界

[Lemo Opuscar 中文说明](https://github.com/lemomo-ai/lemo-opuscar/blob/main/README.zh-CN.md) 将其定位为用代码制作影片的风格工具箱，当前说明列出 59 种风格，并支持改造已有风格和保存个人风格。其画面渲染、声音及合成具有完整工程流程，因此产品保留可审阅的方案和可追踪的制作任务。上游风格按特定模型调校；本项目首版使用严格声明式场景和六个受控适配器，不承诺与上游任意代码工程完全一致，也不将艺术相似度评分作为功能发布门槛。

DSH 负责能力发现、Agent 执行、工程与任务持久化；客户端负责输入、审核、状态和结果展示。用户不需要输入终端指令、安装依赖或理解源码。开发者需要的工程详情放在作品更多操作中，普通流程只呈现对制作决策有帮助的信息。

## 入口和会话归属

- Bot 能力中可勾选“制作风格短片”。有效开启后，会话输入区在角色右侧出现“选择风格”标签；选中后显示已选风格标签。＋菜单同步提供“选择风格”，两处打开同一风格选择界面。
- 关闭能力后，输入区入口、＋菜单入口及已选风格标签同时隐藏。故事、附件与风格草稿仍保留，隐藏风格不参与普通消息发送；重新开启同一 Bot 后恢复风格选择。
- 风格只是当前创作参数，选中时不发起任务。用户发送时才将当前有效的风格选择与创作要求一起带入；实际制作仍须经过方案、权限及费用确认。
- 开关以保存成功后的状态生效；保存失败时保持上次有效状态，保留设置草稿并通过 Toast 提示。能力已开启但服务尚不可运行时允许浏览和保存草稿，制作按钮说明当前限制。
- 每次创作绑定当前 `sessionId`、发起成员和角色上下文。打开工作台或选风格不新建会话、不发起付费任务。
- 风格草稿按“会话＋稳定 Bot 身份”隔离；切换 Bot 显示其自己的有效选择，不沿用前一个 Bot 的隐藏参数。关闭能力或切换 Bot 不取消已接受的任务，任务仍保留原发起身份、方案和配置快照，并可从会话摘要查看。
- 方案确认、待审分镜、制作任务及成片以摘要卡回到原会话。点击摘要恢复对应创作，不复制生成一个新任务。
- 保留原会话文字与附件草稿。取消工作台返回会话；“保存草稿”与“提交制作”是两个明确动作。

## 主流程

| 步骤 | 用户操作 | 页面反馈与下一步 |
| --- | --- | --- |
| 选择风格 | 搜索或按服务端返回的完整分类浏览 | 卡片显示名称、目录封面和当前可用状态；只有 `ready=true` 的风格可以确认使用 |
| 描述短片 | 输入主题或故事，按需带入角色与素材 | 展示可编辑的创作要求；缺少必要信息时逐题补充 |
| 确认方案 | 确认时长、画幅、语言、声音和审核方式 | 汇总本次范围、参考素材用途及真实报价状态 |
| 审阅分镜 | 查看服务端保存的关键镜头与说明 | 可确认制作，或填写整体调整要求生成新的完整分镜修订 |
| 制作中 | 查看真实阶段，可返回会话处理其他事情 | 服务端继续执行；摘要入口保留，恢复后跟进原任务 |
| 查看与调整 | 播放、下载，或从任务卡发起整体调整 | 调整产生新的任务修订；历史版本比较属于后续范围 |

首版每次制作都先看分镜，`storyboardReview` 固定为 `true`。服务端持久保存待审状态，浏览器离开或服务重启后仍能从同一任务继续；尚未开放跳过审核的快速制作。

一次只突出当前步骤的主要动作。已确认的风格、规格和素材折叠为简洁摘要，随时可回看；修改会影响下游内容时，明确列出需要重新生成的范围，再由用户提交。

## Web 和移动端布局

| 场景 | Web 宽度至少 900px | 移动端及窄窗口 |
| --- | --- | --- |
| 选择风格 | 保留会话侧栏，工作区显示分类、搜索和虚拟网格，右侧可预览详情 | 全屏风格页，分类横向滚动；点击卡片进入全屏详情 |
| 填写要求 | 左侧编辑方案，右侧固定画面或规格预览 | 单列填写，规格摘要可展开；底部固定主要动作并避开安全区与键盘 |
| 分镜审核 | 宽面板展示真实预览与说明，审核动作固定可达 | 镜头卡纵向滚动；点击“调整分镜”后自动滚动并聚焦整体调整输入框 |
| 制作中 | 显示最近可用预览、真实阶段和任务摘要 | 显示当前阶段和最近画面，返回会话后以摘要卡继续跟踪 |
| 成片查看 | 播放器与任务状态同屏，产出进入素材库 | 播放器在上，任务与产出入口在下；历史比较属于后续范围 |

风格和分镜使用按需构建的列表或网格。小屏不把桌面的侧栏压缩成不可读列；正文、按钮和审核内容保持可点击尺寸，大字体下允许自然换行。主要动作使用既有胶囊按钮，菜单、弹窗、底部面板和加载状态遵循项目共享组件。

## 风格目录

目录由固定上游版本生成，本版返回 59 项及完整分类、`readyCount` 和结构化不可用原因。界面显示实际总数与可制作数量，支持服务端分类、关键词和分页；空搜索保留原输入。目录加载用本地化骨架卡，分页保留选中项。六个受控适配器优先展示，其他项目仍可浏览但不能选择。

卡片首要信息为上游目录封面、名称及本地化状态说明。未支持、待验证、运行环境不可用和模型不可用分别显示明确文案；原始内部错误或英文 reason 不直接展示。目录封面只用于识别风格，不表示已经为当前用户主题生成影片。

“我的风格”属于后续范围，尚未进入本版 App 和 DSH 合同。未来实现时应保存用户明确确认的风格版本，流程为：

1. 填写用途和希望改变的配色、字体、材质、节奏及声音；保留自由描述入口。
2. 查看调整前后对照和改变范围；基底风格与版本可追溯。
3. 先看由实际绘制流程输出的风格图。可提出修改；不满意时保留当前方案。
4. 用户确认风格图后，生成 demo。时长由服务端支持范围决定，制作前仍需确认实际报价。
5. 播放 demo 后，用户选择“保存为我的风格”“继续调整”或“暂不保存”。只有显式保存才进入个人目录。

调整中草稿与正式风格分开保存。风格更新产生新版本，历史影片仍引用原版本；上游基底更新不自动覆盖用户风格。MVP 可以先提供系统风格创作，将个人风格保存放到后续阶段。

## 方案和审核

基础字段为主题、时长、画幅及输出语言。首版声音只暴露服务端实际认证的 `none` 或 `music`；没有真实音轨证据时不显示 `music`，旁白/TTS 尚未进入请求合同。风格不支持某个规格时展示可选规格及原因，不能在提交时静默替换。

首版风格短片是纯文字原创链路，不接受附件或内容角色。携带 `mediaIds` 或 `contextRoleIds` 的风格短片请求由服务端明确返回 `style_film_references_unsupported`；App 保留文字、附件与风格草稿，普通对话仍可继续使用这些素材。上传入库不能描述为影片模型已经读取，也不能承诺角色一致性。

分镜卡包含镜头序号、真实预览状态、时长、画面内容及当前说明。预览未生成时显示骨架或明确的待生成占位，不把占位图当作审核依据。首版调整以整套分镜为单位，输入节奏、镜头和文案要求后完整重新规划。

## 长任务与恢复

制作属于服务端长任务。客户端呈现实际事件对应的阶段，例如方案准备、分镜待审、画面渲染、声音制作、合成、自检与保存。没有阶段证据时显示“正在制作”，不通过定时器伪造进度、倒计时或完成百分比。加载采用骨架或 loading 图标。

关闭页面、切换会话或刷新后，通过保存的任务标识及最新快照恢复任务。SSE 断开可以重连，阶段和成片以服务端快照校准；多端打开同一任务不会重复提交制作。收到过期事件不能让新版本倒退到旧状态。

“待你确认”是独立状态，审核入口持续保留。普通对话文字完成不代表视频完成；成片只有在文件保存成功并可读取后才进入产出列表。取消或暂停仅在服务端明确支持时展示；操作文案写清停止当前执行与已提交渲染的影响范围。

## 调整与任务修订

待审分镜提供“调整分镜”，用户填写整体修改要求后提交。App 自动滚动并聚焦输入框；服务端以新 revision 完整重新规划并生成新分镜，不承诺单镜局部重算或无损复用。

每次被接受的调整产生独立任务修订，旧 checkpoint 和已入库资产不被覆盖。当前 job 的最新 revision、分镜和允许动作以服务端 snapshot 为准；完成后版本比较和任意历史版本切换属于后续范围。

## 报价与运行门禁

确认页只展示服务端返回且未过期的真实报价，包含计价单位、预估或上限属性、范围与有效期。没有报价时显示“费用待确认”，允许保存方案；付费制作动作保持待确认，不能展示虚构积分、价格或零成本承诺。规格变化、局部修改范围变化或报价过期后重新报价。

能力可运行需要同时满足：DSH 技能已绑定、当前成员与全局能力已授权、受支持模型已配置、渲染和声音所需工具可用，以及工作空间可写。服务端应返回逐项检查结果与用户能理解的原因；客户端以检查结果决定制作入口，不能仅检查技能名称。

服务端在开放制作前检查当前模型、专用 `film_plan_submit` 工具、渲染器、字体、Chrome／headless shell、FFmpeg、工作目录和私有存储；任何一项不可用时目录仍可浏览，但 `ready=false`。发布门槛是这些能力合同、恢复和安全检查可用，不包含持续追加样片或艺术评分；上游特定模型的效果也不作为当前环境的保证。

## 失败和结果未知

- 普通读取、上传、保存或提交请求失败，使用 `AppToast.error` 一次提示，保留文字、素材、选择和已有数据；原“确认”或“开始制作”按钮继续承担再次提交操作。
- 服务端业务任务失败保留失败状态、已完成内容与任务允许的恢复操作。它和普通接口请求失败分开处理。
- 提交超时或连接中断导致结果未知时，持久保存同一个幂等标识；先查询或复用该请求。不得创建新的任务来掩盖不确定状态，不自动重复付费制作。
- 后台自动重连不重复 Toast。取消、过期请求或离开后的迟到响应不得提示或覆盖当前草稿。
- 并发修改发生版本冲突时保留编辑内容，读取新版本并让用户重新确认；不能静默覆盖其他端修改。

## Flutter 接入位置

当前真实 DSH 路径为 `lib/main_harness.dart` → `DemoApp` → `DemoHomePage`，桌面由 `DemoDesktopWorkspace` 承载。正式 `/session` 属于另一套生产会话入口，本轮不改其路由。

| 现有文件或组件 | 可复用职责 |
| --- | --- |
| `demo_chat_page.dart` | 能力入口、原会话审核卡和任务摘要返回入口 |
| `demo_settings_page.dart` | 能力已绑定、可用及授权状态展示 |
| `demo_capability_catalog.dart` | DSH tools、skills、MCP 目录的实际状态 |
| `DemoRepository.loadCapabilityCatalog` | 调用现有能力目录；新增制作业务继续由 Repository 暴露 |
| `conversation_question_card.dart` | DSH 补充问答和确认；保持题目修订、答案与幂等语义 |
| `demo_task_brief_sheet.dart` | 当前任务摘要的视觉与交互模式 |
| `demo_assets_page.dart` 及 `demo_remote_media.dart` | 自有素材展示、鉴权读取及产出查看 |
| `AppVideoPlayer` 及 `AppMediaGallery` | 播放、预览和版本产物的媒体展示 |
| `AppSheet`、`AppDialog`、`AppMenu`、`AppSkeleton`、`AppToast` | 统一反馈与容器规范 |

旧 `ConversationStyleLibrarySheet` 可参考分页虚拟网格和选中确认模式，但其数据是角色画风模板，不能直接当作影片风格目录。

现有六项 `character`、`script`、`image`、`video`、`audio`、`vision` 产品能力保持不变。风格短片使用独立 `memberSkills`，首个 skill ID 为 `lemo-opuscar`；`memberBotIds` 将执行槽绑定到稳定 Bot 身份。`DemoAssistantProfile` 复用稳定身份和技能授权，但不会复制会话草稿、任务或作品。旧配置经 v1→v2 原子迁移后默认不启用技能，自定义旧 Bot 获得持久 `legacy:` 身份。

新增请求统一定义在 `lib/core/network/network_agent_api.dart` 的 `NetworkAgentApi`；feature 的 `data/` 做适配与业务转换，通过 Repository 暴露。Widget 不拼接口、不解析原始 JSON，不处理 Agent 进程、流式解析或持久化。页内筛选、选中和加载状态本地管理；确有跨页共享的创作草稿或任务索引再在 `lib/shared/providers/` 新增职责明确的 Provider。文案同时维护中英文 ARB。

## 已实现后端数据契约

能力目录、消息 invocation、任务快照和审核接口已经通过 `NetworkAgentApi` 与 Repository 接入。服务端仍以运行检查和 compatibility record 决定是否可用；客户端字段不能绕过门禁。

| 领域 | 字段和语义 |
| --- | --- |
| Bot 能力配置 | `memberSkills`、`memberBotIds`、配置修订、授权与可运行状态；旧六项能力保持独立 |
| 运行检查 | 能力标识、绑定与授权、模型和版本、兼容性结果、工具就绪状态、限制原因、检查时间 |
| 风格目录 | 稳定风格 ID、版本、分类、名称、说明、封面与实际示例资产、可用规格、归属、分页游标 |
| 创作草稿 | 草稿 ID、会话与稳定 Bot 身份、执行成员 ID、角色与素材引用、主题和规格、风格版本、审核方式、草稿修订；区分保存的风格与本次有效发送参数 |
| 方案与分镜 | 方案版本、镜头稳定 ID、顺序与时长、画面和声音要求、预览资产状态、审核状态、锁定范围 |
| 报价 | 报价 ID、计价单位、金额或上限、适用方案修订、制作范围、有效期、确认状态 |
| 提交结果 | 消息 `skillInvocation` 与完整 body 共同参与幂等；同一请求号和输入返回同一 film job |
| 任务快照与事件 | session snapshot 的 `filmJobs`，包含任务修订、真实阶段、分镜、产物、允许动作和结构化业务错误 |
| 作品版本 | 作品和版本 ID、父版本、修改说明与范围、关联任务、文件入库状态、自有资产 ID、时长及媒体规格 |
| 个人风格 | 所有者、基底风格版本、调整说明、已确认风格图和 demo 资产、草稿或已保存状态、风格修订 |

任务接受、状态持久化和幂等关联需在同一业务事务内完成。客户端恢复按任务或幂等标识读取最新状态，不自动重放未确定是否被接受的制作请求。作品资产沿用现有鉴权、所有权和自有文件读取机制，不能只保存短期供应商链接。

## MVP 与后续

当前 MVP 已实现系统风格目录、原会话创作草稿、分镜审核、真实制作阶段、刷新与服务重启恢复、成片入库、权限门禁、提交幂等和失败保留草稿。目录固定显示上游 59 项；六个受控适配器按服务端运行检查决定 `ready`，其余 53 项保持不可选择。本版不以继续追加样片或艺术评分作为发布阻塞项。

后续增加附件／角色参考、个人风格图与 demo 审核保存、旁白及字幕精细编辑、完成后版本对比、单镜局部重渲染和跨端通知。首版 `revise` 会完整重新规划并产生新的分镜修订，不承诺局部重算。

## 验收条件

1. Web 900px 以上与 375px 移动宽度均可完整走通选风格、填写、审核和查看成片；键盘、大字体和安全区不遮挡主要操作。
2. 工作台进入、选风格和返回不会新建会话或提交任务；发送时才带入当前有效风格。同一创作始终回到原会话，其他会话和 Bot 的风格草稿不受影响。
3. 目录读取固定上游版本的 59 项真实分页结果、完整分类及 `readyCount`；选择在翻页和返回后保留，未支持或当前运行不可用的项目显示本地化原因且不能选择。
4. 首版必须先审分镜；待审任务刷新和服务重启后仍能继续，旧修订不能误确认新方案。
5. 模型或运行环境不可用、权限不足、工具未就绪或报价缺失时不能启动制作，用户仍可浏览目录并保存草稿。
6. 提交失败保留所有输入和素材；超时后复用幂等标识，重复点击、多端提交和刷新不会产生重复任务。
7. 页面只呈现服务端真实阶段；文字结束不把媒体标为完成，保存失败不把不可读取文件当作成片。
8. 关闭页面再打开、SSE 重连及服务恢复后跟进原任务；过期事件与迟到请求不覆盖新修订。
9. 请求错误通过一次 Toast 展示，无额外错误面板；业务任务失败保留业务状态及服务端允许的恢复动作。
10. `revise` 不覆盖旧分镜 checkpoint 或旧资产；完成的视频使用明确的当前 job/revision 资产 ID。完成后版本切换属于后续范围，不在首版伪造入口。
11. 正式实现通过 `flutter pub get`、`flutter analyze`、`flutter test`，覆盖幂等、修订冲突、刷新恢复、权限门禁及两端布局。设计原型检查交互路径、溢出与操作可达性，不作为后端接入或模型兼容验收证据。

13. 开关保存失败维持上次有效状态并保留设置草稿；切换 Bot 不串用风格，关闭能力不取消已有任务，原任务及产出仍可查看。新增能力须由服务端认可，不向现有六项白名单提交未知 ID。
